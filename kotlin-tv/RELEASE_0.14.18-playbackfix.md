# 红果 TV 0.14.18 连播修复

并存包 `com.hongguotv.nativeapp.playbackfix`，版本 `0.14.18-playbackfix`，versionCode `33`，最低 Android 8 / API 26。原包构建版本为 `0.14.18-local`，覆盖原应用仍需原私钥。

## 问题与改动

### 预加载失败后仍复用失败资源

此前 Media3 报告下一集预加载失败时，只移除了预加载管理器中的媒体源，应用自己的 `preparedNext` 仍保留同一份 `RemoteVideo`。自动切集会再次取用这份失败资源；尤其在备用地址对应另一份 MP4、资源一致性检查已拒绝继续读取时，复用同一实例无法恢复。

每份预加载现在携带任务版本与资源标识。失败回调只清理仍属于该次预加载的资源，取消对应请求并释放网络连接；切集走正常取流流程。已经交给播放器、已取消的任务或后来的新预加载不会被旧回调误清理。正常成功的预加载仍可交给播放器继续使用。

### 部分集数只返回不兼容编码

不同集数可能返回不同编码和分辨率。此前成功的 V5 GET 返回 ByteVC2 后，客户端过滤不支持的编码就直接失败，没有继续请求电视兼容资源。

在成功、匹配所选分集且只有 ByteVC2 的响应下，使用同一播放身份，对播放专用接口发起一次 V5 POST，申请兼容资源。新增回退只处理明确的编码不兼容；业务拒绝、模型损坏、缺少解密信息或任意网络错误不会被混同为这一条件。POST 签名绑定实际发送的 gzip 字节；原 GET 固定验证向量、搜索和账号协议保持独立。

### 自然 ByteVC2 失败样本恢复

实测《全球死考：刚下刑场你让我去考试第六季》193 集版本的第 153 集，剧集 ID `7704857878514895896`，分集 ID `7704857946630409240`：

- 原 V5 GET 返回 HTTP 200，所选分集匹配，5 个清晰度全部为 ByteVC2。
- 新逻辑自然触发一次 V5 gzip POST，仍用同一匿名身份；HTTP 200 返回同一分集的 5 个 H.265 资源。
- 选中 720P HEVC / AAC，完整读取 1,365,640 字节，首尾严格解码通过，分别为 90 / 89 帧。
- 全程 6 次真实 HTTP 请求，没有模拟响应、没有旧 POST，也没有重复注册身份。

这是一个真实网络上的兼容资源恢复结果；不等于实体电视自动推进已经验收。上述两组后测均使用 SHA-256 为 `8be6967688959a3d99f5d5b9fc631685c5a59838a0f4f88455957174a903122c` 的核心构建，运行前后未变。

### 设备验收边界

当前环境没有连接 Android 设备，也没有可运行的 Android TV 模拟器，因此实体电视的自动换集、遥控器操作、硬件解码及长时间连播尚未现场验收。针对失败预加载的设备测试可以编译，但编译成功不等于已执行。

`PreloadAcceptance` 现包含真实 Media3 预加载失败回调的故障注入，检查当前集继续播放、失败资源被清理，以及下一集重新取流后的首帧与 `STATE_ENDED` 时间；原成功预加载交接与低内存取消检查继续保留。CI 会编译设备测试 APK，实际执行仍需设备。
